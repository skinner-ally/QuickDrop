# stage6-amb-world

Задача: пакет «amb-world» этапа 6 (spec-stage6 §4.1, §4.2) — мир по координатам (`src/lib/ambient/world.ts`) и правило
полян (`src/lib/ambient/clearing.ts`) с тестами.

Статус: готово

## Результат
- `world.ts`: перенос расстановки `mockup/forest.js` один к одному (h2/vn/density, objectsOf, pondOf, pondD), наружу
  px мира. Экспорты по спецификации + добавлены: `hashU32` (целочисленный h2), `OBJECT_CLEAR` (рамки полян по виду),
  `POND_REACH_PAD = 56`, `pondBox(p)` (рамка пруда x ± r·1.45, y ± r·1.1), `compareObjects` (порядок (y, x, id)).
- Границы `Bounds` во всех запросах — включительно (как `queryBounds` графа).
- `id` объектов — не хеш, а взаимно однозначный номер места (хеш h2 давал ~10 % совпадений на соседних местах):
  лес >= 0 по (qx, qy), камыши/кувшинки < 0 по (sx, sy, i); целые до 2⁴⁶. Пруд — номер ячейки.
- Кувшинки генерируются всегда (в мокапе в зиме их нет): в зимней сцене `SceneArt.object('lily')` должен вернуть null.
- `clearing.ts`: корзины 128 px, подпись — сумма хешей точных битов координат + число точек; бесконечные рамки
  допустимы (обход всех корзин).

## Тесты
- `world.test.ts` (20): сверка с эталонной копией формул мокапа (hash2, valueNoise, density, объекты 169 ячеек, пруды
  121 ячейки, pondDistance), детерминизм (обратный порядок прогрева, сброс и переполнение кэша), отрицательные координаты,
  уникальность id, ≤ 64 на ячейку, пределы SPRITE_LIMITS, рамки полян, объект не в воде, доля прудов 0.42 ± 0.05
  (2000 ячеек), пруд в ячейке, сортировка и стыки, pondsIn, мелочь земли (5 на клетку, разбиение).
- `clearing.test.ts` (13): near/inBox на границах, через корзины, отрицательные координаты; signature/key; дерево
  100 выше / 200 выше / 60 ниже / 80 сбоку; pondCleared.
- `npm run typecheck` и `npm test` (66 файлов, 1993 теста) проходят.
