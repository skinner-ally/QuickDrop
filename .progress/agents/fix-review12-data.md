# fix-review12-data

Задача: исправления по ревью этапов 1–2 в области «data» (6 находок: корзина из копии и автоочистка;
настройки автокопий в копии; положения нод из копии поверх занятых клеток; положения при смене категории
слиянием; распознанный текст при слиянии; сброс backupLastAt в «Удалить все данные»).

Статус: готово

Предыдущий запуск оборвался: в `exportImport.ts` уже были правки находок 1–3 (без тестов, тесты падали).
Правки сверены с находками и оставлены; доведено: тесты, находки 4–6.

## Что исправлено

1. **Корзина из копии стиралась первой автоочисткой** (`importBackup`). Перед записью у победивших записей
   с `deletedAt` старше `now − (trashDays − min(trashDays, 7))·сутки` отметка поднимается до этой границы:
   запись живёт в корзине ещё 7 суток (или весь срок, если он короче). Срок — тот, что будет действовать после
   импорта: replace — из копии, без него — здешний; merge — здешний (`isValidSetting`, иначе умолчание).
   `trashDays = 0` — отметки не трогаются; непросроченные переносятся точно. `sanitizeItem` не менялся.
   Экспорт: `IMPORTED_TRASH_GRACE_DAYS = 7`.
2. **`backupEvery`/`backupKeep` больше не переносятся копией**: добавлены в `PRIVATE_SETTINGS`, комментарий дополнен.
3. **Положения нод из копии на занятых клетках**: положение из копии пишется, только если его клетка
   (`snapToGrid`) свободна от всех локальных положений (включая скрытые записи) и от уже принятых из той же
   копии (в порядке копии; действует и при replace). Отвергнутое → `skipped`, место даст автораскладка.
4. **Р8 при слиянии**: если победила версия из копии с другой категорией — локальное положение удаляется.
   Положение из копии пишется только при совпадении категории записи в копии с итоговой (после
   `repairIntegrity`; поэтому блок положений перенесён после починки целостности). Положение для записи,
   которой нет в разделе `items` копии, не берётся.
5. **Распознанный текст при слиянии**: `withNewerOcr` — для того же `fileId` берётся более свежий `ocrAt`
   (с `ocrText` или без него — «пробовали, текста нет») из проигравшей версии; в обе стороны: если осталась
   локальная запись, а в копии распознавание свежее, оно дописывается без смены `updatedAt`.
6. **`clearAllData` не сбрасывает `backupLastAt`** (убран из `CLEARED_SETTINGS`): иначе первая же запись/демо
   после стирания вызывала автокопию почти пустой базы и обрезку рабочих копий.

  (replace из копии / здешний, merge здешний); `trashDays = 0`; локальный победитель в корзине не трогается.
  Положения: занятая клетка (локальная, скрытая, внутри копии), старая копия после окончательного удаления,
  replace с двумя положениями в одной клетке, Р8 (смена категории слиянием снимает положение), положение
  при другой итоговой категории и при категории, убранной починкой. OCR: 4 теста. Настройки: `PORTABLE`
  без ключей копий, они не экспортируются, чужая копия не меняет здешние `backupEvery`/`backupKeep`.
  Прежние проверки точного `deletedAt` переведены на свежие метки; координаты в тесте «локальное положение
  сильнее» разведены по клеткам; тест версии 1 (merge) — локальная запись в той же категории.
