# fix-review12-logic

Задача: исправления по ревью этапов 1–2 в области «logic» (src/search/**, src/hooks/**, src/store/**, src/lib/* кроме
областей tauri/data/theme, vite.config.ts, src/main.tsx и их тесты). 18 находок: PDF (очередь, обход, worker),
сохранённые поиски, is:trash, экспорт Markdown, граф, тексты ошибок, индекс поиска.

Статус: готово (повторный запуск; предыдущий оборвался, правок в области не оставил — сверено по времени файлов)

## Исправлено

1. **Очередь извлечения текста PDF** (находки 5, 7, 11) — `src/lib/ocr.ts`. Все разборы (создание записи и фоновый
   обход) идут по одному через общую цепочку промисов. `running` ставится сразу, до очереди: повторный вызов по той же
   записи — тот же промис. В очереди задача заново читает запись (могла исчезнуть или уже получить ocrAt), сигнал,
   прерванный во время ожидания, даёт `skipped` без разбора. Отсчёт 30 с и чтение файла начинаются, когда подошла
   очередь. Предложение «не ставить ocrAt при обрезке по времени» не принято (так и рекомендовал проверяющий).
2. **Неустранимые отказы PDF** (находки 3, 6). `PdfTextResult.permanent: true` у «больше 50 МБ», `PasswordException`,
   `InvalidPDFException` (`src/lib/pdfText.ts`). `extractItemText` при таком отказе и при «Файл не найден» ставит
   отметку ocrAt без текста (уже извлечённый текст при повторе с force не затирается) и возвращает `failed` с текстом.
   Тайм-аут и сбои движка — временные, отметки нет.
3. **Обход backfill** (находки 3, 6). Без `.limit()`: перебираются все кандидаты; `limit` считает обработанные, неудач за
   вызов тоже не больше `limit`; записи, давшие неудачу, до перезапуска не пробуются (`Set` в модуле). Новый
   `drainPdfBackfill(pauseMs = 3000)` — порции по 10 с паузой, пока есть что пробовать (гарантированно завершается);
   `src/main.tsx` вызывает его вместо одиночного `backfillPdfText()`.
4. **Зависший worker pdf.js** (находка 4) — `src/lib/pdfEngine.ts`. Свой `Worker` на документ
   (`PDFWorker.create({ port })`, `getDocument({ worker })`), единая уборка: `task.destroy()` ждётся не больше 1 с,
   затем `PDFWorker.destroy()` и `worker.terminate()`. `PdfEngine.open(data, signal?)`: `pdfText` по прерыванию и по
   времени на этапе открытия абортит свой сигнал — движок уничтожает worker. Ошибка загрузки worker отклоняет открытие
   (pdf.js не переходит на разбор в главном потоке). `disableWorkerRendering: true`. `createPdfEngine(pdfjs, makeWorker?)`
   — без фабрики (тесты в Node) поведение прежнее.
5. **Индекс поиска заранее** (находка 2, п. 1). `prepareSearchIndexAsync(items, categories)` в `src/search/engine.ts`:
   строит индекс порциями (100 записей или 200 тыс. символов) с передачей управления; не ставит индекс поверх сброса или
   поверх уже построенного поиском. `isSearchIndexReady()`. `src/hooks/useItems.ts`: после снимка, пока индекса нет —
   `requestIdleCallback` (запасной `setTimeout`) читает категории тем же запросом, что `useCategories`, и строит индекс.
6. **composeQuery: типы** (находка 9) — `src/search/serialize.ts`, `src/search/query.ts` (`withoutTypeOperators`,
   позиции токенов в `lex`). При типах и в фильтре, и в строке (type:/has:) пишется пересечение одним оператором, а
   type:/has: из строки убираются; пустое пересечение — побеждают типы строки (как cat:), закреплено тестом.
7. **Свой диапазон дат** (находка 10). `serializeFilter(…, now, { relativeDates: false })` и тот же 5-й параметр у
   `composeQuery`: пара from/to всегда пишется датами. По умолчанию — как раньше (тип `SerializeOptions` экспортирован).
8. **Ограда в пункте списка** (находка 13) — `src/lib/wikiLinks.ts`: `unclosedFence` возвращает ограду с отступом
   открывающей строки; проверено разбором micromark (одноразовый скрипт вне репозитория).
9. **Запись вне плана экспорта** (находка 14) — `src/lib/markdownExport.ts`: имя получает суффикс из id
   («План (3f2c9a1e).md»), не совпадает с заметкой плана и не затирает её файл.
10. **«README.md.md»** (находка 15): конечное «.md» в имени заметки срезается (до и после обрезки длины).
11. **Невидимые символы в именах файлов** (находка 16): `safeFileName` удаляет U+061C, U+200B, U+200E/F, U+202A–202E,
    U+2060–2064, U+2066–2069, U+FEFF; U+200C/U+200D сохраняются (письменности, эмодзи).
12. **Тесты graphLayout** (находка 18): остановка `findFreeSpot` по кольцам, притяжение к центру зоны
    (`CENTER_WEIGHT`), две сохранённые ноды в одной клетке. Мутационная проверка: оба мутанта из находки теперь ловятся.

Каждое исправление поведения закрыто тестом; новые тесты ocr прогнаны против прежней реализации — 7 падают.
